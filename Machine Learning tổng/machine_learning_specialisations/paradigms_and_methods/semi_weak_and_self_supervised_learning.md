# Semi-Supervised, Weakly Supervised, and Self-Supervised Learning

> This is an overlay on the [shared 16-phase lifecycle](../../machine_learning_lifecycle_phases/README.md), not an independent lifecycle. Apply the core to every stage and add these controls whenever unlabelled examples, noisy/programmatic labels, or constructed pretext targets provide learning signal.

## Use this guide when

Use it when labelled and unlabelled examples are combined for one task; labels come from rules, distant supervision, annotator aggregation, or label models; or targets are constructed from the data through masking, prediction, reconstruction, or contrastive views before downstream adaptation.

## Do not confuse it with

- Unsupervised clustering discovers structure; self-supervision constructs a training target for representation learning.
- Weak supervision concerns imperfect label sources; semi-supervision concerns the mixture of labelled and unlabelled examples. A project may use both.
- Data augmentation alone is not a self-supervised objective, although augmentation may define positive views.
- Synthetic examples are governed additionally by the [generative systems](../task_families/generative_modelling_and_content_generation.md) guide.

## Scope and major variants

Covered variants include self-training and pseudo-labelling, consistency regularisation, graph-based label propagation, positive–unlabelled settings when explicitly defined, programmatic/weak label aggregation, masked or predictive pretraining, reconstruction, and contrastive representation learning. The downstream task and modality remain owned by their overlays.

## Problem and data contract

Assign each record a pool and label-status field: trusted/gold, human-labelled, weakly labelled with source identities, pseudo-labelled with producing model/version/confidence, or unlabelled. Document source dependencies, abstentions, conflicts, class-conditional coverage, and whether examples are reused across stages. For self-supervision, specify the pretext target, view/masking policy, positive/negative semantics, and invariances it assumes; these choices define the learned signal rather than neutral preprocessing.

## Split and evaluation protocol

Split the independent real-world unit before creating views, pairs, pseudo-labels, or graph edges. Keep the locked test set outside label-model fitting, teacher inference used for selection, threshold tuning, negative mining, and representation selection. Trusted validation/test labels must not be generated by the same rules being evaluated. If labelled and unlabelled pools differ, report source/time/domain composition and evaluate the intended deployment population separately.

## Baselines and model-family choices

Required comparisons are labelled-only training under the same gold-label budget; a simple heuristic or majority vote for weak sources; and a frozen-representation/linear-probe baseline for self-supervised pretraining where meaningful. Add ablations removing each major source, unlabelled pool, or pretext stage. Compare equal-data, equal-label, and—when central to the claim—equal-compute conditions rather than crediting an objective for extra resources.

## Training and validation adaptations

Version all teacher checkpoints, label functions, label models, source weights, thresholds, augmentation/view policies, negative-sampling logic, masking schedules, and iteration counts. Prevent circular validation: a pseudo-label-producing model must not learn from labels or predictions derived from the evaluation fold. Track pseudo-label acceptance and class distribution by iteration. Stop or roll back when confidence filtering collapses coverage, amplifies imbalance, or degrades trusted validation evidence.

## Metrics and uncertainty

Primary success remains downstream performance on trusted labels using task-owned metrics. Add label-source coverage, abstention/conflict rates, pseudo-label acceptance and trusted-label precision by confidence band, label-efficiency curves, and per-stage transfer results. For representation claims, predeclare probe/adaptation protocol and datasets. Report uncertainty on the trusted evaluation unit; large unlabelled sample counts do not increase the number of independent gold outcomes.

## Error analysis, safety, and robustness

Inspect error inheritance from each weak source, confirmation bias across pseudo-label iterations, rare-class erosion, shortcut features induced by pretext tasks, false negatives in contrastive sampling, and domain gaps between labelled/unlabelled pools. Slice by source agreement, confidence, stage, class and deployment group. Treat high confidence as a model output requiring calibration evidence, not proof of correctness.

## Packaging, deployment, monitoring, and maintenance

Package the final model together with any deployed teacher, representation encoder, label model, rule set, thresholds, view/tokenisation policy, and provenance lineage. Monitoring must separate real labelled outcomes from pseudo/weak labels and watch pool composition, rule coverage/conflict, confidence/acceptance rates, class balance, representation drift, and gold-set performance. A rule edit, teacher replacement, new unlabelled pool, pretext-objective change, or pseudo-label refresh is a material update requiring regression and contamination checks.

## Minimum completion checklist

- [ ] Every stage and example pool has an explicit signal type, provenance, and owner.
- [ ] Gold evaluation labels are independent of weak rules, teachers, pseudo-labels, and selection decisions.
- [ ] Splitting precedes view, pair, graph-edge, pseudo-label, and label-model construction.
- [ ] Labelled-only, simple source, frozen-representation, and source/stage ablations are reported as applicable.
- [ ] Thresholds, sources, teachers, views, negatives, masking, seeds, and iteration histories are versioned.
- [ ] Trusted-set performance, label efficiency, source diagnostics, slices, and uncertainty are reported.
- [ ] Monitoring and rollback cover source drift, feedback amplification, and every material signal refresh.
